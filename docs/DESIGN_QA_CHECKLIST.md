# Evidue Design QA Checklist

Use this checklist on every public route at 1440 px, 1024 px, and 390 px widths.

## Brand

- [ ] Product is called Evidue; no retired sub-brand appears.
- [ ] Wordmark/mark does not use wallet, robot, sparkle, or shield imagery.
- [ ] Page leads with the buyer's financial question.
- [ ] Copy is direct, contractual, and evidence-led.
- [ ] Synthetic-data disclosure is visible.

## Hierarchy

- [ ] One primary action is visually dominant.
- [ ] One primary work surface exists per page.
- [ ] Corrected payable amount is dominant after reconciliation.
- [ ] Supporting facts are not rendered as unnecessary equal cards.
- [ ] Page title appears once.
- [ ] Technical metadata is secondary but accessible.

## Components

- [ ] Tables are used for real cross-reference tasks.
- [ ] Small sets use lists rather than tables/cards.
- [ ] Row detail opens in a drawer and preserves context.
- [ ] Filters are compact and clearable.
- [ ] Dialogs are reserved for blocking or confirmatory tasks.
- [ ] Empty states explain why and what happens next.

## Visual consistency

- [ ] No decorative gradient, glow, glass, or neon treatment.
- [ ] Radius, border, spacing, and typography use system tokens.
- [ ] Standard panels do not use shadows.
- [ ] Status color is paired with text.
- [ ] Green/red/amber are used only for real semantic states.
- [ ] Money, IDs, hashes, and timestamps use tabular/mono treatment.

## Trust and truthfulness

- [ ] LLM is described only as proposing rules.
- [ ] Human approval/versioning is explicit.
- [ ] Deterministic execution is explicit.
- [ ] No real integration or customer is implied.
- [ ] No unsupported allegation of fraud or overbilling appears.
- [ ] Every displayed amount can be traced to backend data.

## Interaction

- [ ] Keyboard focus is visible.
- [ ] Drawer focus is trapped and returns to the triggering row.
- [ ] Direct links and refresh work.
- [ ] Public mode contains no active-looking mutation control.
- [ ] Loading states name the operation.
- [ ] Errors explain impact and next action.

## Responsive

- [ ] Primary financial values remain visible without horizontal scrolling.
- [ ] Navigation becomes a drawer.
- [ ] Contract split view becomes tabs or stacked panes.
- [ ] Evidence detail becomes full-screen on mobile.
- [ ] Low-priority table columns hide before horizontal scroll.
